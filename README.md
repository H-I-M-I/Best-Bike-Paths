# Best Bike Paths 
### Requirements Engineering and Software Architecture

A software engineering project focused on specifying and designing a platform for recording cycling trips, sharing bike path conditions, and discovering suitable cycling routes.

Developed for the **Software Engineering 2** course at **Politecnico di Milano**, academic year **2025–2026**.

## Overview

Cyclists need information about route suitability, road conditions, and obstacles when planning their journeys. Best Bike Paths (BBP) addresses this need through a proposed platform that combines personal trip recording with community-contributed information about bike paths.

The project covers requirements analysis and system design. Its main deliverables are a **Requirements Analysis and Specification Document (RASD)** and a **Design Document (DD)**.

## System Capabilities

The proposed system supports:

- **Trip recording:** Record cycling trips and review statistics such as distance and average speed.
- **Weather information:** Enrich recorded trips with weather conditions when external data is available.
- **Manual path reporting:** Submit information about bike paths, their condition, and relevant obstacles.
- **Automatic data collection:** Use GPS and mobile sensor data to reconstruct routes and identify potential road problems.
- **Report confirmation:** Allow users to review and correct automatically collected information before publication.
- **Route discovery:** Search for bike paths between an origin and a destination and compare routes based on their condition and suitability.
- **Community information aggregation:** Combine published reports while considering their freshness and supporting contributions.

These capabilities describe the target system. This repository focuses on its specification and design.

## Project Deliverables

### Requirements Analysis and Specification Document (RASD)

Defines the problem, expected system behaviour, and constraints, including:

- System goals, scope, and domain assumptions.
- User scenarios and use cases.
- Functional and non-functional requirements.
- Domain and behavioural models.
- External interface requirements.
- Formal modelling using Alloy.

### Design Document (DD)

Describes how the requirements map to a proposed technical solution, including:

- System architecture and component responsibilities.
- Component interfaces and interactions.
- Deployment and runtime views.
- Architectural styles and design decisions.
- User interface wireframes.
- Traceability between requirements and design elements.
- Implementation, integration, and testing plans.

## Engineering Approach

The project connects requirements analysis with architectural design:

1. Analyse the problem and identify user needs.
2. Define system boundaries, assumptions, and constraints.
3. Specify requirements and describe user interactions.
4. Model the system using UML and Alloy.
5. Define components, interfaces, and runtime interactions.
6. Map requirements to the corresponding design elements.
7. Plan implementation, integration, and testing.
