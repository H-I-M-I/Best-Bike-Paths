This section describes the design of the user interface of the \textit{Best Bike Paths (BBP)} system.
The user interface is conceived as a mobile application and is designed to support the interaction scenarios defined in the Requirement Analysis and Specification Document (RASD).
Given the context of use of the application, which is mainly during cycling activities, the interface prioritizes clarity, immediate feedback, and minimal user interaction while moving, delegating confirmation and editing tasks to moments when the user is stationary. 

\subsection{Overview}

The BBP user interface is centered around a map-based mobile view, which represents the primary interaction point between the user and the system.
Through the map interface, users can visualize bike paths, recorded trips, detected or reported issues, and suggested routes.
All core functionalities of the system, such as trip recording, path search, and path information contribution, are accessible through clearly identifiable actions available on the main interface.

\subsection{Key Screens and Workflows}

The user interaction with the BBP system is structured around a set of key screens that support the main workflows defined in the RASD.
The main map interface represents the starting point for most interactions and provides access to the core functionalities of the application.

A typical workflow for trip recording starts from the main map interface, where the user initiates the recording of a cycling activity.
During the trip, the recording interface visualizes the ongoing path while limiting user interaction.
Once the trip is completed, the user is guided to the issue confirmation interface, where automatically detected issues can be reviewed and validated before publication.

Another key workflow concerns path search.
From the main map interface, the user can access the path search interface, specify a source and a destination, and visualize one or more suggested bike paths ranked according to their suitability.
Manual insertion of path-related information follows a similar workflow, starting from the main interface and leading to a dedicated interaction for data input and confirmation.

\subsection{Interface Conventions and Legends}

The user interface figures presented in this section adopt a set of visual conventions to clearly and consistently convey information to the user.
These conventions are used across all interfaces of the BBP mobile application and are summarized below to facilitate interpretation of the graphical elements.

\paragraph{Path Color Coding}

Bike paths displayed on the map are represented using different colors to indicate their overall quality and suitability for cycling.
Green-colored segments denote paths that are considered highly suitable, based on aggregated user contributions and validated information.
Yellow segments represent paths with medium suitability, which may present minor issues or limitations.
Red segments highlight paths with low suitability, indicating the presence of significant issues or unfavorable conditions.
This color coding allows users to quickly assess the quality of available routes at a glance.

\paragraph{Point Markers}

Point markers are used on the map to highlight specific locations associated with relevant events or conditions.
Markers may represent automatically detected issues, user-reported obstacles, or other noteworthy elements along a bike path.
Each marker is positioned at the corresponding geographic location and is visually distinguishable from the path segments to attract the user’s attention.

\paragraph{Issue and Obstacle Indicators}

Different marker symbols are used to distinguish among various types of issues.
For example, warning symbols may indicate obstacles such as potholes or road works, while location pins are used to mark the position of detected or reported issues.
These indicators support the user in identifying critical points along a route and understanding the nature of the reported problem.

\paragraph{Information Panels}

Information panels are used to display additional details related to paths, issues, or recorded trips.
Such panels may include attributes such as path name, length, estimated quality, or issue type and severity.
By providing structured contextual information, these panels enable users to make informed decisions without overloading the map view.

\paragraph{Recording Status Indicators}

During trip recording, the interface includes explicit visual cues to indicate the current recording status.
These cues may consist of highlighted paths, status labels, or dedicated interface elements signaling that the recording is active.
This ensures that users are always aware of whether a cycling activity is being recorded.

\paragraph{Legend Box}

A legend box is included within the interface to summarize the meaning of colors, markers, and symbols used on the map.
The legend provides a compact reference that allows users to quickly understand the visual language of the application without requiring additional explanation.

\subsection{Accessibility and Interaction Notes}

The BBP user interface is designed with particular attention to accessibility and mobile interaction constraints.
Given that the application is mainly used during cycling activities, the interface minimizes the need for complex interactions while the user is moving, favoring large touch targets and clear visual feedback.

Color coding is used to convey information about path quality; however, textual labels and legends are also provided to ensure that information remains understandable regardless of color perception.
Confirmation and editing actions are intentionally deferred to moments when the user is stationary, reducing cognitive load and improving safety.
These design choices aim to ensure that the application remains usable and accessible in real-world usage conditions.

\subsection{Navigation Flow}

The navigation among the different user interfaces is designed to be simple and coherent.
From the main map interface, users can access the trip recording interface to start a cycling activity or the path search interface to compute a suitable route.
Upon completion of a trip, users are guided to the issue confirmation interface to validate automatically detected information.
Additional functionalities, such as manual path insertion and access to trip statistics, are reachable from the main interface through dedicated actions.
This navigation structure ensures that the core functionalities of the BBP system are easily accessible while maintaining a clear separation between data collection, confirmation, and visualization activities.
